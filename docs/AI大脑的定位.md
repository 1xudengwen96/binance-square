# AI 大脑：现在在干什么，应该干什么

> 配套阅读：[体系与路线图](体系与路线图.md)。本文只回答一个问题——大脑在这个项目里的定位对不对。

## 一句话结论

**大脑现在站在价值链的最底端，而项目真正冻在源代码里的部分它一个都碰不到。**

它能做的只有：读测量结果 → 说 1–3 句「下一步该试什么」→ 以置信度 0.35 存进记忆 → 其中一部分被短贴的润色层当措辞参考捡走。

它不能做的包括：提出一个新假设、退休一个旧假设、改一个参数、影响长文。这四件恰好就是「自我优化」的全部内容。

---

## 一、它现在在干什么（精确到调用点）

全仓只有一个任务接了大脑：

| 位置 | 做什么 |
| --- | --- |
| `src/brain/author.ts:64` | `brain.ask({ purpose: 'reflect', ... })` —— **唯一**的大脑调用 |
| `src/daemon.ts:218` | 每天一次（20 小时闸门）自动触发 |
| `src/server/app.ts:346` | 面板按钮手动触发 |

输入是最近 30 天 7 条假设的 `median/样本数`，加一句「这些实验还差多少样本」。
输出被要求是 1–3 条「下一步该试什么」，每条必须能被现有指标验证。

输出的去向：

```
brain 的一句话
   ↓  remember(kind='engine-model', key='brain:next:{i}', confidence=0.35, ttl=7天)
brain_memory
   ↓  recall() 按相关度+置信度+证据数+引用次数+新近度排序
brief() / writingNotes()
   ↓  作为 polish() 的第 5 个参数
润色层的提示词里，标着【只影响取舍与措辞，不得放宽上面任何一条硬性限制】
```

**这条通路只通到短贴，而且比看起来更窄。**

- `src/studio/runner.ts:350` 调的是 `polish(cfg, a.body, facts)` —— 第四个 `persona` 和第五个 `notes` 参数都没传。**长文润色既收不到记忆，也收不到人设。**
- `src/rank/playbook.ts:69` 的 `recall` 明确只要 `kinds: ['rank-rule', 'content-lesson']`，**不含大脑写的那一类 `engine-model`**。也就是说决定「几个标签 / 带不带图 / 陈述还是提问」的 playbook 完全看不到大脑的建议。

大脑唯一真正生效的地方，就是短贴润色层那段备注。

## 一之二、现状盘点：这四件事，今天 AI 能做吗

先说一个前提：**大脑是活的，不是待接线状态。** 线上 `llmEnabled = true`，`brainFor()` 返回真实的 Brain（`openai / gpt-6.1-sol`，走 `api.sunskii.com/v1` 中转）。上一轮把 `reflect` 挂进 daemon 之后，它每天会真的发起一次模型调用。

那么它能做的和不能做的：

| 该做的事 | 今天能做吗 | 缺什么 |
| --- | --- | --- |
| 每天说「下一步该试什么」 | **能，已在跑** | — |
| 建议渗进短贴措辞 | **能，已在跑**（但受相关度打分影响，见下） | — |
| 影响长文 | **不能** | `runner.ts:350` 少传两个参数，一行代码的事 |
| 影响实验决策（标签数/图/句式） | **不能** | `playbook.ts:69` 的 `recall` 明确排除了 `engine-model` 这一类 |
| 提出新假设 / 退休旧假设 | **不能** | 22 张表里没有假设表；`HYPOTHESES` 是源码常量数组 |
| 提议改参数并自动回滚 | **不能** | 没有 pending-change 机制，也没有任何回滚记录 |
| 矛盾检测 | **部分能，但不是大脑做的** | 见下 |

**矛盾检测这一块，系统里已经有一个在运转的实现** —— `src/studio/evidence.ts` 的 `checkClaims()`：把已发布长文里的可证伪断言拿去跟当前市场数据比，被推翻就写一条 `studio_lessons(kind='contradicted')` 并把该概念标记为 stale，同时**也记录「仍然成立」的**（注释写得很对：只记意外的账号会学错基础比率）。

这是真的自我纠错，而且是这套系统里除模版权重之外唯一一处。但它是**确定性代码，不经过大脑**，而且只覆盖长文断言 —— rank 规则、`categoryWeights`、模版权重这三个地方完全没有对应机制。要做第 4 件事，形状照抄它就行，不用从零设计。

**还有一个当前状态下的巧合值得记一笔**：`recall()` 的相关度是 `about`（信号名 + 币种 + 风格）与记忆文本的 bigram 重叠 × 3，再加 confidence × 1.5。大脑写的「试试把币种放在第二句」跟「资金费率 BTC 专业」几乎没有字面重叠，相关度接近 0，全靠 0.35 的置信度撑着。现在记忆账本里 `rank-rule` 一条活跃的都没有（那条假规则被撤销了），所以大脑的建议**暂时**能被捞进前 6 条。等实测规则开始积累，它们会稳定排在前面，大脑那条通路会自然变窄 —— 这是设计意图（实测压倒猜测），但意味着**现在不接线，以后接的成本更高**。

这不是推测。线上账本现在正是这个状态：`rank-rule` 活跃 0 条，`engine-model` 活跃 3 条，三条的 `use_count` 都已经是 4 —— **大脑的话确实被写作层捡走了 4 次**。通路是通的。

但看看它说了什么：

> · 固定其他发帖条件，对比自绘 K 线图与纯文字帖，补齐样本后比较分发中位数。
> · 保持主题和正文一致，仅改变主题标签数量，对比话题页收录表现。
> · 保持正文内容一致，仅改变是否以问句收尾，对比评论表现。

这三条是 `h_chart`、`h_hashtag_count`、`h_opening` 三条假设的**同义复述**。系统在问「下一步该试什么」，模型把已经登记在源码里的三条实验念了一遍。

**这就是当前定位的完整写照**：接线是通的，调用是真实的，钱是花了的，而产出是零信息量 —— 因为它能看到的只有那张表，能影响的只有措辞。它没有能力说出表上没有的东西，因为说出来了也没地方放。

## 二、为什么这不够：整个系统只有一处能自己改自己

我把「不需要人改源代码就能被程序修改的状态」全查了一遍：

| 状态 | 谁能改 | 频率 |
| --- | --- | --- |
| `templates.weight` | `tuneTemplateWeights()` | 每轮 tick |
| `settings.paused` | 发布连续失败时自动暂停 | 出错时 |
| `brain_memory` | `scoreAll` 写规则、大脑写建议 | 每天 |
| **其余全部** | **只有人改代码或在面板手填** | — |

而「其余全部」里包含的正是决定系统行为的东西：

- **`HYPOTHESES`** —— 硬编码数组（`src/rank/hypotheses.ts`），只被 `experiments.ts:47` 和 `score.ts:145` 两处消费。**系统能检验假设，但不能提出假设，也不能退休假设。** 想加一条，得我改源码。
- **`categoryWeights`** —— 注释写着「种自竞品账号的实测中位数：行情异动 128 / 市场情绪 170 / 快讯 98 浏览，全网热搜 3」。种下去之后**再没被写过一次**。这是全系统最该自我修正的参数：它直接决定队列里各类素材的配比，而竞品三个月前的中位数不是今天的真相。
- `coinSignalCooldownMinutes`、`EXPLORE_SHARE`、`RECHECK_SHARE`、`REPEAT_EXPLORE_SHARE`、`CONFIDENCE_TO_ACT`、`MIN_VIEWS_FOR_CREDIT`、`TTL_MINUTES` —— 全是常量或手填。

**结论：`tuneTemplateWeights` 是目前唯一在运转的自我优化回路，而它是确定性的，跟大脑无关。** 大脑被接在了一个不影响任何决策的位置上。

这不是大脑不够聪明，是接线接错了地方。

## 三、它应该干什么（按杠杆从高到低）

### 1. 假设的提出与退休 —— 登记表应该是数据，不是代码

这是最大的一块。现在的闭环是「登记假设 → 分配臂 → 测量 → 出结论」，缺的是**闭环的入口和出口**：谁来决定该测什么、什么时候该停止测一件已经被推翻的事。

改法：`hypotheses` 表进数据库，`registry(store)` = 内置 7 条 + 数据库里的。大脑读 verdicts 和记忆，提议新假设——但**只能用封闭词汇表**：

- 臂必须是系统里已经存在的旋钮（带不带图 / 标签数 / 收尾句式 / 字数带 / 时段带 / 重发间隔）
- 指标必须是 `Metric` 里已有的四个之一
- 必须写出可被证伪的一句话

表达不出来的就不是假设，是感想，不许占用发帖配额。同时上限 2 条大脑提出的活跃假设，防止它一天发明五个然后每个都拿不到样本。

**退休同样重要**：一条假设连续 N 天 `样本不足` 且没有新臂进来，应该被标记为「测不动」并从探索预算里摘出去，而不是永远占着 35% 的随机流量。

### 2. 参数提议，带界、带到期日、带自动回滚

`categoryWeights` 和 `coinSignalCooldownMinutes` 是最该动的两个。但**绝不能让模型直接写参数**——那是把方向盘交给一个看不见路的司机。

照抄 `tuneTemplateWeights` 已经验证过的形状：

```
提议（附理由 + 预声明的回滚条件）
   ↓
落库为 pending-change，带上生效窗口
   ↓
有界应用：单次不超过 ±25%，一次只动一个参数
   ↓
窗口内测量目标指标
   ↓
没改善 → 自动回滚，并把「试过、没用」写进记忆
```

最后一步是关键。**回滚和记录失败，比应用更改更重要**——否则同一个错误参数会被反复提议、反复应用，系统会记得「我改过」但不会记得「改了没用」。

### 3. 长文接上记忆（最小、最快、马上能做）

`polishArticleDraft` 里像短贴那样取一次 `writingNotes` 传进第四个参数就行，`brief` 已经支持复用 verdicts，不用重算。

长文恰恰是大脑最该发挥的地方：结构、取舍、下一篇该问什么。现在它是唯一完全没接线的路径。

### 4. 矛盾检测

这是真正的「模型形状」的任务，而且**在小样本下就有用**，不用等量起来：

- 「三周前你写下『晚上发帖更好』，但最近 10 条里晚上的中位数更低」
- 「这条规则的置信度是 0.76，但它只有一个分层支撑」
- 「模板 A 的权重被调高了 3 次，可它的浏览量一直没跟上」

判断一小堆证据之间是否自相矛盾，是模板做不了、而模型擅长的。而且它便宜：不需要生成，只需要读。

## 四、它永远不该干什么

这些不是靠提示词约束的，是结构上做不到的，必须保持：

| 不做 | 为什么 |
| --- | --- |
| **不写正文** | 正文是模板从素材拼的，事实全部来自市场数据。模型会编数字，这是结构问题不是提示词问题。合规上这也是账号被限制的最直接路径。 |
| **不选币** | 热度池是确定性、可审计的。让模型选币等于让不可复现的判断进入调度。 |
| **不决定发帖时刻** | `schedule.ts` 是平台滥用检测意义上的硬闸门（同分钟撞车、跨号突发）。 |
| **不做事实来源** | 置信度上限永远 0.35，实测规则是 0.72+。一条 AI 建议在排序上不可能盖过一个测量结论。 |
| **不改 `Settings` 以外的任何持久状态** | 密钥、账号绑定、模板正文都不在它的权限里。 |

## 五、贯穿全部的设计原则

> **每一次大脑的影响力，都必须带一个可测量的到期日。**

一条建议要么被落成臂、能被实验证伪；要么在 TTL 内自动消失。一个被应用的参数改动要么在窗口内证明有效、要么自动回滚并留下「试过没用」的记录。

这条原则不是洁癖。这套系统第一次线上运行就产生过一个假规则（「深夜发帖浏览量翻倍」，实际是那几个晚上币恰好热），差点被写进长期记忆去指导写作。**一个没有到期日的自我优化系统，会稳定地退化成自我说服。** 大脑越强，这条原则越重要，不是越不重要。

## 六、已落地（本文写作之后发生的事）

上面第 1–4 项全部已实现，不是计划。逐条对应：

| 文档里的判断 | 现在 |
| --- | --- |
| 长文润色收不到记忆和人设 | 已修：`polishArticleDraft` 取 `writingNotes` 并传入人设。**这一条用本地 HTTP 桩断言了真的发出了什么** —— 少传参数不报错，只有读发出请求才能挡住 |
| 大脑只能复述已登记的假设 | 已修：登记表进数据库（`hypotheses` 表），`registry(store)` = 内置 7 条 + 库内 active。新登记的假设不改一行源码就能被分配臂、被分层、被判规则 |
| 提议没有词汇表约束 | 已修：`propose()` 只接受「已有维度 × 已有指标」，复述已占用的组合直接拒；`experiment` 必须落在写作层真能驱动的旋钮上，观测维度伪装成实验被拒。理由文本会回灌给下一轮反思 |
| 大脑不能碰参数 | 已修：`param_changes` 表 + 四道闸门（白名单 / ±25% / 同时只有一个在途 / 到期自动判定，没改善**或判不出来**都回滚并写「别再提这个值」） |
| 规则只会积累不会失效 | 已修：`revokeStaleRules()`。旧代码只在 `rule`/`flat` 时写记忆，一条降级成「线索」的规则会永远 active |
| 没有矛盾检测 | 已修（第一块）：规则降级即撤销。长文侧 `checkClaims()` 本来就在跑，形状被照抄 |

顺带拆掉的一个耦合：`armOf()` 原来 `switch (h.id)`，意味着新增一个 id 的假设**永远拿不到臂**，且看起来像"测了但没发现"。现在按维度分派，登记表才真的可扩展。

删掉两个说谎的东西：`EXPLORE_SHARE = 0.35`（从未被使用，实际行为是无信念时 100% 均匀探索）；`reflect()` 里那段把 `scoreAll` 刚写的详细规则覆盖成简短版的重复写入。

面板新增「系统能改自己的两个地方」一张卡：待审批提议（可批准/拒绝）、可调旋钮当前值与合法区间、参数改动台账（含被拒与回滚的理由）。

**发帖量、日额度、间隔、活跃时段仍然不在机器可动的范围内**，并有测试钉住。

## 七、还剩什么

按危险程度从低到高：

1. **样本量。** 这是唯一真正卡住一切的东西。237 个测试验证的是判断逻辑正确，不是已经测出结论。
2. **转化数据仍为 0 行** —— 只有操作者能录。
3. **`categoryWeights` 现在*可以*被调整了，但还没有*应该*被调整的证据。** 机制先于结论存在是对的，前提是机制不会自己造结论 —— 这点由「没有可比历史样本就拒绝应用」那条闸门保证。
4. 大脑目前没有额度上限以外的刹车：它一天最多提 2 条假设、1 条参数改动，但**没有人格漂移检测**。如果哪天它开始稳定输出「还不知道」以外的东西，那需要一条新的告警，不是新的权限。

当初判断的顺序与实际上发生的：

| 原定顺序 | 判断对不对 |
| --- | --- |
| 1. 长文接上记忆 | 对，半小时的事，且是当时唯一没接线的路径 |
| 2. 矛盾检测（小样本就有用） | 对，而且比预想的更急 —— 查的时候发现了一条真 bug：规则降级后不会失效，旧代码只在 `rule`/`flat` 时写记忆 |
| 3. 样本吞吐 | 对，这是前提（已在上一轮修：保质期背压） |
| 4. 每天录转化数字 | **仍未做，且只有操作者能做** |
| 5. 登记表变成数据 | 顺序错。它比预想的便宜，因为真正的难点不是搬表而是那套封闭词汇表校验；校验一旦存在，登记表本身几乎是顺带的 |
| 6. 有界参数提议，"最后做，因为它最危险" | 判断成立，实现也确实放在最后。危险不是靠顺序消掉的，是靠四道闸门消掉的 |

**一句话复盘**：这个功能里真正有价值的部分不是「让大脑能改东西」，而是「让它改的东西必须可测量」。前者一行代码，后者才是全部工作量。

## 八、怎么判断它真的在自我优化了

不是看它说了多少条建议，是看这四个数：

- **假设登记表的条目数在变** —— 有进有出，而不是永远的 7 条。
- **`categoryWeights` 有过被程序修改的记录**，且每次修改都能在事件日志里追溯到理由和回滚条件。
- **记忆里存在「试过、没用」的条目** —— 一个只记成功不记失败的系统没有在优化，它在积累偏见。
- **大脑建议的存活率** —— `brain:next:*` 里有多少条活过了 7 天 TTL 并被实验证伪或证实。存活率 100% 说明它只在说安全的话，0% 说明它在编。两者都该报警。
