# squareforge · 体系与路线图

这份文档说清三件事：**这套系统到底在优化什么**、**它现在是怎么运作的**、**接下来要做的是什么**。
用法和安装看 [README](../README.md)，这里不讲操作步骤。

---

## 一、目标链条

```
内容被广场推荐  →  有人读  →  有人点 $币种 / 链接  →  有人开户交易  →  返佣  →  关注  →  更多返佣
```

**只有第一环是机器能自动测到的，最后一环是真正付钱的。** 中间几环平台不给接口。
整套系统的设计都围绕一个后果：一个只优化"浏览量"的机器人，会熟练地生产出不挣钱的内容。

所以现在的立场是：

| 环节 | 怎么拿到 | 可信度 |
|---|---|---|
| 被推荐 | 分档回看浏览量曲线（20 分钟 / 1 / 3 / 8 / 24 / 72 小时）+ 是否出现在公开榜 | 自动，实测 |
| 被读完 | 赞 / 评 / 转 / 长文订阅数 | 自动，实测 |
| 点击 · 返佣 · 新增粉丝 | **操作者每天把币安后台的数字抄进来一次**（30 秒） | 手填，按浏览量加权摊到每条帖子 —— 是近似，不是账单 |

不接交易所 API Key：那个 Key 能提现能交易。系统只拿广场 Key（只有发帖权限）。

## 二、现在怎么运作

### 2.1 内容从哪来

```
采集（币安行情 / 广场热度榜 / 快讯 / 公告 / Hyperliquid / DEX / 情绪 / 持仓异动 / 均线）
  → 素材（带保质期：多空比、费率一小时后就是错的陈述）
  → 模版渲染（结构、数字、合规都在模版里，不在模型嘴里）
  → 事实台账（正文每个数字都要有出处）
  → AI 润色（可选：只许改写，不许新增数字或币种，改完回比台账）
  → 闸门 → 排期 → 发布 → 回抓效果
```

**分工是固定的：广场决定写哪个币，市场数据决定能说什么。** 没有对应市场数据的币，宁可不发，也不含糊地写。

### 2.2 三道闸门（都在必经之路上，不是文档里的约定）

| 闸门 | 拦什么 | 在哪 |
|---|---|---|
| 事实台账 | 凭空出现的数字、币种 | 生成时 + 润色后 + **发布前** |
| 合规 | 敏感词、买卖指令、目标价、收益承诺、免责声明缺失 | 生成时 + **发布前对最终字节再查一遍** |
| 重复 | 指纹冷却、结构相似度、跨账号撞句、同币同信号 12 小时冷却 | 生成时 + 发布前 |

免责声明由 **publisher 补上**，不靠每个调用点记得写 —— 曾经靠调用点，结果 12 条里漏了 4 条。

### 2.3 节奏

- 生成侧按**队列**预留分钟（否则一批草稿全挤在同一分钟）。
- 发布闸门按**时钟**判到没到点（否则未来的草稿会挡住现在该发的，实测造成 7 小时空档）。
- 队列深度封顶 = 当天时段能发完的条数；排期一旦落到明天就停止生成（不写过夜就过期的草稿）。
- 长文有自己的间隔（赛道设定 5 小时一篇），不是"生成即发布"。

### 2.4 一个记忆账本

`brain_memory` 存所有长期判断：流量引擎测出的规则、内容教训、读者事实、AI 的建议。
**追加后推翻**，不删除 —— 被推翻的旧判断留着，因为"我们曾经以为 X"本身能防止同一个错每周重学一遍。
每条带：出处、置信度、证据条数、被引用次数、可选过期时间。

### 2.5 可插拔的 AI 大脑

`src/brain/brain.ts` 一个接口，底下走厂商无关的 `chat()`（OpenAI 兼容中转 / Anthropic / 本地端点都行）。

**它是顾问，不是事实来源。** 能改写、排序、指出矛盾、提下一步该试什么；不能新增任何数字、币种、时间跨度，不能给买卖建议。它写进记忆的东西置信度固定 0.35，标成"待验证假设"。
**关掉大脑，整套系统照常运转** —— 规则由测量直接得出，不依赖模型。

**调度器每天跑一次反思**（20 小时闸门，不是每轮）：把测量结果沉淀成记忆，并在配了大脑时问它"下一步该试什么"。这一步以前只有面板上那个按钮会触发 —— 一个需要人去点的"自动迭代"不是自动迭代。放每天而不是每轮，是因为它是唯一会花钱调模型的地方，而它读的证据（24h / 72h 检查点）本来也不会一分钟一变。

**但大脑现在的接线位置不对** —— 它只能影响短贴措辞，碰不到假设登记表、参数、长文。定位问题与改造方案见 **[AI 大脑的定位](AI大脑的定位.md)**。

## 三、流量引擎：怎么问一个读不到的算法

流程是硬编码的，没有捷径：

```
登记可证伪的假设 → 发帖前随机分配实验臂并落库 → 曲线换算成分发事实
  → 层内比较 + 时间对半复现 → 够格才升为规则 → 写进记忆 → 下次写作前被读到
```

### 三条不许绕的规矩

1. **观察类假设永远不能升为规则。** 历史替你选的臂不是随机分配的臂，效应量再大也只是线索。
   （这条是抓了现行之后定的：引擎一度把"深夜发帖浏览量翻倍"当成规则，真相是深夜那几条正好是热币的忙夜。）
2. **只在层内比较**（格子 × 热度带），且**至少 2 层**。浏览量最大的影响因素是哪个币、它当时多热，比写法的影响大一到两个数量级；混着比测的是运气。
3. **发现集与验证集按时间切开**，后半段必须复现。面板把"混比值"和"分层值"并排显示。

### 现在的 10 条假设

| 假设 | 类型 | 状态（2026-10-10，17 条帖子） |
|---|---|---|
| 带 K 线图比纯文字拿到更多分发 | 实验 | 攒样本中（每臂 0 条） |
| 标签数量影响进话题页 | 实验 | 攒样本中 |
| 问句收尾换不来更多评论 | 实验 | 攒样本中（互动率列已修，每千次浏览才有读数） |
| **首句先给方向、数字挪到第二句** | 实验 | 新增，来自官方 3 秒定律 |
| **带一句对形态的解读更受推荐** | 实验 | 新增，来自官方「观点」项 |
| **结尾求关注能提高关注转化** | 实验 | 新增，官方明确允许「求关注」禁止「刷关注」 |
| 信息密度高的长帖更受分发 | 观察 | 线索：短 85 / 中 113 / 长 259（长帖仅 2 条） |
| 发帖时刻决定首小时推送 | 观察 | 线索：午后 101 / 晚 165 / 深夜 239（混比 122%，分层后 2 层） |
| 同币同类信号短期内再发会被自我压制 | 观察 | 攒样本中 |
| 上过榜的帖子首小时增速更高 | 观察 | **17 条全部未上榜，两臂恒等，测不动** |

**默认答案是"样本不足"。** 如果哪天它一口气给出三条规则，那更可能是噪声在敲门。

最后一条值得单独记：它想比较"上过的"和"没上过的"，而**上过的数量是 0**，所以这条假设在当前账号状态下不可能产生任何结论。这不是设计缺陷，是它诚实——引擎读不到东西的时候就说读不到。它同时也说明：**先要解决"能不能被推荐"，才有东西可测。**

### 币安自己说它要什么（2026-10-10 记录）

广场官方创作者学院发过一份内容诊断清单（帖子 364497166654961，1.8 万浏览）。它给的公式是：

- 交易内容：**看涨跌 + 观点 + 晒单**
- 事件内容：**事件 + 配图/视频 + 个人观点 + 真实晒单**
- **3 秒定律**：开头抓不住人，后面写再好也没用
- 涨粉允许「结尾自然地求关注」，明确禁止刷关注
- 红线：**虚假新闻（AI 事实验证失败直接没流量）**、一味蹭热门币、重复内容、过量表情、评论机器人

对照我们发出的 17 篇，实测结果（用公开读接口逐条查回）：

| 检查项 | 结果 |
| --- | --- |
| `isCreatedByAI` | 17/17 = false —— **没有被判成 AI** |
| 事实核查 | 只触发过 1 次，结果 UNSURE（非 FAIL）—— **不是瓶颈** |
| 挂了交易对 | 17/17 = 100%（同期在榜帖子只有 63%）—— 这块已做到位 |
| 首句 | 全部是 `$币 + 数字`，没有一句观点，没有求关注 |

同时验证了一个**差点被我当成结论的东西**：每条帖子的 `recommend` / `highQuality` 都是 false，看着像"这就是不上榜的原因"。去测基线才发现 —— 那条 157 万浏览的帖子这两个旗标也是 false，40 条在榜样本里 true 的数量为 0。**这两个字段在该接口里不填充，没有信号**。先测基线再下结论，这条规矩第一次救了我自己。

所以缺的是官方公式里的**观点**和**首句**两项，而第三项「晒单」这个账号拿不出来 —— 账号不做真实交易，而官方明确把「持仓和晒单不匹配」「假截图」列为会做没账号权重的行为。

据此新增：

- 三个真旋钮 `hook_form` / `stance` / `follow_cta`（`src/content/voice.ts`），**默认全部关闭**，只有实验臂分配到的帖子才会带上
- 派生句**结构上不含任何数字**，所以它们不可能发明事实；台账里没有支撑方向时就返回 null，宁可少一个样本也不写没依据的句子
- 新合规闸门：**拦下一切第一人称持仓/交易声称**（「我刚建了多单」「我的仓位」「晒一下我的持仓」）。这条是硬闸门不是提示词，因为润色层和人工改写都可能在生成之后才引入它
- 摘掉 6 个模板里内嵌的 `{{#maybe 35}}{{@cta.follow}}` —— 它会让 `h_follow_cta` 的**对照臂有三分之一概率自己冒出求关注**，那样测出来的不是求关注的效果，是噪声
- `symbolDailyCap`（默认 3，滚动 24 小时，跨品类）：现有冷却只挡「同币同类」，所以同币换名目可以连发八条，而官方点名这正是伤账号健康度的行为

官方建议在这里仍然是**先验，不是规则**：它被登记成三条带臂、带指标、带样本地板的假设，和当初那条「深夜发帖翻倍」走同一道门。



### 冷却时长不是拍的

`coinSignalCooldownMinutes`（同币同信号 12 小时）本身就是被上面那台机器调的旋钮之一 —— 它测的是"隔多久再写同一个币还有观众吗"。

但这里有个自我锁死的坑：冷却本身保证了"6 小时内重发"这一臂**永远拿不到样本**，于是那个 supposedly 由测量决定的数字，其实一直由直觉决定。所以有 **5% 的帖子会按确定性哈希故意绕过冷却**（同素材+同号+同时段永远同一结论，事后可审计）。代价是这部分帖子可能确实更差 —— 而那正是要测的东西。

### 草稿不写注定作废的

素材有保质期（`market_move` 90 分钟、`funding` 180、`attention` 240），生成侧却曾经可以往 **24 小时后**占位。队列上限数的是"待发布条数"，而作废会把条数还回去 —— 于是形成一个自激振荡：写一批 → 过期作废 → 上限重新打开 → 再写一批。2026-10-08 那天的实测结果是 **写了 100 条草稿，发出去 9 条**。

现在生成侧占位之后立刻检查 `slot.at >= expiresAt(category, occurredAt)`，超了就不写；素材池的候选窗口也从"一律 6 小时"改成**按各品类自己的保质期**过滤，免得一条已经过期的信号白占一个池位、挤掉真正还能发的。上限从此数的是"能活到发布时刻的草稿"，变成了真正的背压。

## 四、已完成

- 采集 9 个源、76 个模版、事实台账、结构去重、多账号矩阵与币分配
- 长文工作室：独立表、赛道人设硬锁、概念阶梯、断言复核（被数据推翻会记账并标记概念待重写）
- **两处自我修改**（详见 [AI 大脑的定位](AI大脑的定位.md)）：假设登记表从源码常量变成数据库（新假设不改一行代码就能被分配臂、分层、判规则）；参数旋钮可被有界调整（白名单 / ±25% / 同时一个在途 / 到期自动判定，**判不出来也回滚**）。发帖量、日额度、间隔、时段不在其中，并有测试钉住
- 规则失效即撤销：旧代码只在结论成立时写记忆，一条降级成「线索」的规则会永远 active
- 面板：设计令牌 + 组件体系，侧栏分组导航，账号岗位一页看清，数据板（时间轴 / 间隔 / 分时段 / 归因），流量引擎页（假设卡 / 分发形状 / 记忆账本 / 待审批提议 / 参数改动台账）
- 节奏：生成侧预留 + 发布侧到点 + 队列封顶 + **保质期背压（不写注定作废的草稿）** + 长文间隔 + 文章计入同一 Key 的日额度
- 合规：发布前对最终字节复查；信息量下限（≥3 个独立数字）；主题标签；**第一人称持仓/交易声称一律拦下（该账号不做真实交易）**
- 运维：每晚自动备份（`VACUUM INTO`，保留 7 份，过期报警）；每日反思；`scripts/cadence.ts`、`thin-check.ts`、`rank-report.ts` 三个诊断脚本
- 243 个测试，`tsc --noEmit` 干净

## 五、接下来要做（按优先级）

### P0 · 让钱进入闭环
1. **每天录入后台数字**（只有你能做）。录满 7 天后，把 `targetMetric` 切到 `money`，让实验按"每千次浏览返佣"判定。
2. 归因质量升级：从"按浏览量加权"改成按**上榜 + 增速**加权，因为那才是"被推荐"的证据。
3. 面板加一条曲线：每天「返佣 / 千次浏览」的趋势，和发帖量画在一起。

### P1 · 让结论配得上样本
4. 分层再加一维：**同币对照**（同一个币的不同臂，最干净的比较，需要攒够重复）。
5. ~~假设登记表加"预注册"约束：登记后不许改测量口径，防止事后挑数据。~~ **已做**：臂永远从维度定义取（`DIMENSIONS[dimension].arms`），指标在登记时锁定且改指标等于登记一条新假设，所以「事后换个口径再算一遍」这条路结构上不存在。
6. 序贯检验：规则成立后再跑一个等长的确认窗口才允许影响写法。

### P2 · 内容侧
7. 极端费率的专用表述（|年化|>300% 时不给年化，现在只能少一个数字）—— 这是信息量闸门挡住一批费率帖的根因。
8. 长文的概念阶梯扩到第二层（当前只有交易认知一条赛道、12 个概念，其中 4 个因缺数据源写不了）。
9. 标题：长文标题的点击率没有任何度量手段，先设计一个能测的代理（比如同一概念的两种标题轮流发）。

### P3 · 运维与风险
10. 备份目前是本地目录，需要一份异地（对象存储 / 另一块盘）。
11. 多账号共用一个出口 IP 是平台判定关联账号最直接的信号 —— 加号之前要先解决代理。
12. **仓库是公开的**：历史提交里有一个 `.env` 带着真实形态的飞书 webhook，需要清理历史或直接废弃那个 webhook；聊天里明文贴过的 GitHub PAT 应撤销。

## 六、明确不做的事

- **不做多租户 / 不做 SaaS。** 单用户本地工具，唯一的硬上限是币安 100 帖/天/Key。
- **不做纯 LLM 生成。** 模型会编数字，这是结构问题不是提示词问题。
- **不做跟单 / 带单 / 目标价 / 点位。** 合规上会限制账号，方向上也不是我们能长期做的事。
- **不追竞品的模版数量**（751 个）。 measured 下来有效多样性比数量重要。
- **不接交易所 API Key。** 那个 Key 能提现能交易。
