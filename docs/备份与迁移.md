# S3 备份与服务器迁移

面板入口：**系统 → 备份与迁移**，可以直接打开 `/#backup`。

当前项目桶：`squareforge-backups-tokyo-3a6476ddd6`，地区 `ap-northeast-1`，目录 `backups/`。

## 自动备份

默认每 6 小时执行一次全量备份。归档包括：

- SQLite 一致性快照：账号与业务密钥、设置、素材、内容、效果数据、实验和 AI 记忆。
- 当前图片目录中的常规图片文件。
- 版本、主要表行数、文件大小与 SHA-256 校验清单。

业务暂停、关闭自动循环或自动发布时，面板进程中的 S3 定时器仍然运行。进程需要保持运行；重启时会检查是否到期，失败后约 15 分钟重试。周期可在页面选择 1、3、6、12、24 小时。默认周期对应正常运行时最多约 6 小时的数据恢复窗口，实际以最近成功记录为准。

上传使用 HTTPS、SSE-S3 加密及 SHA-256 校验，成功后再次读取 S3 对象头验证。当前桶阻止公开访问并拒绝非 HTTPS 请求。使用 S3 Standard，每份归档使用独立对象名。

连接测试和每次备份会检查备份目录的 30 天生命周期规则；缺失时创建，保留其他目录的规则。到期由 S3 异步清理，不保证恰好满 30 天立即消失。未完成的分片上传在 1 天后清理。

S3 连接保存在数据目录的 `backup-config.json`，权限为 0600，接口只返回凭据是否存在及掩码。任务状态另存于 `backup-state.json`，重启后保留。这两个文件、服务器登录密码、本地旧备份和导入前副本不进入 S3 归档。原有本地备份机制继续保留。

## 迁移到新服务器

1. 在新服务器部署本项目，设置新服务器的面板登录密码并启动。
2. 打开“备份与迁移”，填写上面的桶名、地区，以及有权限的 AWS 凭据，保存配置。
3. 点击“测试已保存连接”，确认连接及 30 天保留规则正常。
4. 点击“一键导入最新备份”，也可以在列表中选择较早的归档，确认导入。
5. 导入完成后检查账号、内容和图片。确认旧服务器已经停止，再恢复业务运行和自动发布。

导入先完成下载、归档 SHA-256、逐文件校验、数据库完整性及外键检查，再处理当前服务器的数据。文件路径会映射到新服务器的图片目录，数据库按当前版本迁移。归档中的软链接、硬链接、路径越界、重复文件和未登记文件会被拒绝。

导入完成时，`autoRun`、`autoPublish` 均关闭，并设置暂停原因，避免旧备份中的发布配置在新旧服务器上同时生效。S3 连接配置及新服务器的登录密码保持原样。每次导入前的数据库和图片保存在本机 `data/restore-history/<导入编号>/`；数据库替换失败时会尝试恢复当前数据库与图片。

如果新旧服务器在迁移时都继续写入，最新云端备份之后的旧服务器数据不会自动合并。正式切换应先停止旧服务器的业务写入、执行一次“立即备份”，再从新服务器导入该归档。恢复操作期间不要运行额外的 CLI daemon 或其他直接写同一数据库的进程。

## 手动操作与故障排查

Docker 中执行一次备份或列出归档：

```bash
docker compose exec squareforge node --import tsx src/backup/cli.ts backup
docker compose exec squareforge node --import tsx src/backup/cli.ts list
docker compose exec squareforge node --import tsx src/backup/cli.ts status
```

原生运行：`npm run backup:s3`、`npm run backup:list`。

面板会显示任务阶段、最近成功、下一次到期时间和错误信息；失败也会写入事件。若桶没有生命周期规则读写权限，连接测试或备份会明确失败，防止在没有保留策略的情况下持续堆积归档。

凭据至少需要当前桶的 `s3:ListBucket`、`s3:GetBucketLocation`、`s3:GetLifecycleConfiguration`、`s3:PutLifecycleConfiguration`，以及备份目录内的 `s3:PutObject`、`s3:GetObject`、`s3:DeleteObject`（连接测试清理临时对象使用）。初次创建桶所需的管理权限不需要提供给日常备份任务。

当前单份压缩归档上限 4 GiB，解压总量上限 20 GiB；超过限制会失败，不会上传一份不完整的归档。数据增长接近上限时应改为分片上传或分层备份。

## 验收依据

自动化测试覆盖：数据库与图片往返恢复、旧服务器路径映射、新服务器凭据保留、恢复后停止自动发布、恢复前副本、损坏归档及不安全归档拦截、业务暂停时自动备份、重启后的周期判断、失败重试与临时文件清理、任务互斥和接口访问控制。

2026-10-21 已在正式服务开启每 6 小时备份，并完成首份真实 S3 上传（10,054,293 字节，40 张图片）。独立核验对象 SHA-256、AES256 加密、禁止公开访问和 30 天生命周期规则。

同日使用独立空数据库、独立数据卷和仅本机可访问的面板，通过真实浏览器点击“一键导入最新备份”完成恢复。恢复后 SQLite 完整性为 `ok`、外键错误为 0；2 个账号、2,074 条素材、25 篇内容、AI 记忆及其他业务表行数与归档一致，40 张图片通过校验。新实例登录凭据和 S3 配置保留，自动运行、自动发布均关闭；导入前副本存在。演练实例与数据卷已清理，未对正式数据库执行恢复。

参考：[S3 生命周期过期](https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-expire-general-considerations.html)、[SSE-S3 加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingServerSideEncryption.html)。
