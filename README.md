# squareforge

本地单用户的币安广场（Binance Square）内容工厂：**采集市场与广场热度 → 用模版生成带事实校验的帖子 → 配合约 K 线图 → 人工审核或按节奏自动发布 → 回抓效果调模版权重**。

只跑在你自己的机器上，监听 `127.0.0.1`，没有多用户、没有配额系统。

> 这套系统在优化什么、怎么运作、接下来做什么 —— 见 **[体系与路线图](docs/体系与路线图.md)**。

---

## 快速开始

```bash
npm install
cp .env.example .env        # 可选：也可以全部在面板里填
npm run db:init             # 建库 + 同步内置模版
npm start                   # 打开 http://127.0.0.1:8787
```

面板里点 **抓取素材 → 生成草稿 → 通过 → 演练发布** 就是完整链路。

**面板自己就是调度器**：启动后每 `tickMinutes`（默认 15 分钟）自动跑一轮「采集 → 过期清理 → 分币给各号 → 起草稿 → 采样统计」，不需要另外起进程。设置页「自动循环」可关。

需要独立跑（比如面板不开、只要后台）时仍然可以：

```bash
npx tsx src/cli.ts daemon 15          # 每 15 分钟一轮（演练，不发）
npx tsx src/cli.ts daemon 15 --live   # 配合设置里的「自动发布」才会真发
```

## Docker 部署

```bash
docker compose up -d --build      # 构建并后台启动
docker compose logs -f            # 看调度日志
docker compose down               # 停止（数据留在 ./data）
```

然后打开 http://127.0.0.1:8787。

**几个刻意的决定：**

| 决定 | 原因 |
|---|---|
| 基础镜像用 `bookworm-slim`，不用 Alpine | `sharp` 和 `better-sqlite3` 提供 glibc 预编译包；musl 上会退化成源码编译，得往镜像里塞 python3 + 编译器 |
| 端口只映射到 `127.0.0.1:8787` | 面板**没有登录**，只校验 Host / Origin / 自定义头。映射成 `0.0.0.0` 等于让任何能连到这个端口的主机改你的排期、覆盖你的 Key、往你账号发帖。这样绑之后可达范围和本地直接跑是一样的 |
| 容器内 `HOST=0.0.0.0` | 容器里的 loopback 宿主进不去，必须监听所有网卡；对外隔离靠上面那条端口映射 |
| `devDependencies` 留在镜像里 | 源码之间用显式 `.ts` 后缀互相 import，而 `allowImportingTsExtensions` 要求 `noEmit` —— 没有编译产物可拷，`tsx` 是运行时依赖 |
| `./data` 挂出来 | SQLite 里存着广场发帖 Key 和 K 线 PNG。**别把这个目录放在网盘/同步盘上** |
| `.dockerignore` 排除 `data/`、`.env` | 否则凭据会被烧进镜像层，任何能 pull 镜像的人都拿得走 |
| 非 root 用户运行 | 镜像里 `USER squareforge` |

**验证状态（要说清楚）**：本机没有 Docker，所以**镜像没有被构建和运行过**。已经验证的是：`node --import tsx src/server/app.ts` 这个入口命令可用、`/healthz` 真实返回 200、healthcheck 那条 node 单行命令实测退出码 0、compose YAML 能被 js-yaml 正常解析、Dockerfile 里 `COPY` 的四个路径都存在、空卷下 `data/charts` 会被自动创建。**没有验证的是**：`npm ci` 在 linux/amd64 上能否顺利装上 sharp 与 better-sqlite3 的预编译包。第一次 `docker compose build` 请盯着看，如果报的是这两个包，就需要在镜像里补构建工具链。

## 账号矩阵

「账号」页管理多个广场号，每个号一套独立配置：

| 维度 | 每号独立的东西 |
|---|---|
| 凭据 | 自己的广场 Key（存在账号作用域的密钥位，接口永不回传明文） |
| 出口 | 自己的代理地址；未配代理的号会在页面上被标红提示「共用出口 IP」 |
| 内容 | **风格可多选**（每帖从选中集合里随机挑一种）+ 语气补充（进润色提示，但不得放宽事实校验） |
| 模版 | **每号屏蔽模版**：把同一个模版在两个号上错开屏蔽，可强制两号用不相交的模版集 |
| 范围 | 素材来源多选、只发这些币、**不发这些币**（黑名单大小写不敏感） |
| 节奏 | 自己的档位（轻松 12 / 标准 24 / 积极 40 / 自定义，实时回显「平均每 N 分钟一帖」）、最小间隔、发帖时段、错峰偏移 |
| 发布 | 自己的发布方式：先审核 / 自动发布 / 跟随全局 |
| 语言 | 简体 / 繁體 |

**「预览几条」**按该号完整配置（风格集、模版屏蔽、来源、黑名单、跨号硬闸）真实生成，但**不入库、不占素材、不上币独占锁** —— 看一眼不会改变它实际会发什么。

**内容为什么不会撞车**，四道机制：

1. **分币而不是分写法** —— 热度池的币按分数轮转分配给各号，一个币在一轮里只会给一个号。
2. **币独占锁** —— `attention_claims` 带 `account_id`，一个号占住某币后，`crossAccountCoinExclusionMinutes`（默认 6 小时）内其他号拿不到它。
3. **人设分流** —— 生成 seed 含 accountId，同义词池与条件分支因此各号不同；style 决定候选模版集合。
4. **跨账号硬闸** —— 起草稿时和发布前各查一次：与其他号近期文案的结构相似度 ≥ 0.62 就拒绝（同账号自己的冷却阈值是 0.85）。发布前被拒的会退回草稿并写明是和哪个号撞的。

素材一旦被写成草稿就标记为已用，所以下一个号的候选列表天然不重叠。

**生命周期**：每个类目有自己的保质期（行情异动 90 分钟、多空比 2 小时、费率/榜单 3 小时、快讯 6 小时、公告 12 小时…），过期且没用过的素材自动作废；超过 `dataRetentionDays` 的素材/样本/日志硬删除；没人引用的 K 线 PNG 也会被清掉。数据只保持新鲜，不会越堆越多。

## 安全模型（重要）

- **广场 Key 只需要发帖权限。** 绝不要把交易所 API Key / Secret 填进来——那种能碰钱。写接口鉴权只有一个 header（`X-Square-OpenAPI-Key`），没有签名步骤，与"只能发帖"的说法一致。
- **Key 存在本机 SQLite**（`data/`，已 gitignore），接口永不回传明文，面板只显示 `sk-••••abcd`。
- **面板有跨站防护**：写操作要求 Host 是本机回环、Origin 不是外站、且必须带自定义头 `X-Squareforge: ui`。缺任意一条返回 403。这是为了防止你开着面板浏览网页时，别的页面向本地端口发请求改设置或触发发布。
- **默认人工审核**。`autoPublish` 关着，`publish` 不加 `--live` 只演练。
- **`content/add` 返回 504/502/503 时绝不自动重试**。这个响应意味着"帖子很可能已经发出去了，只是没拿到 ID"，重试就是重复发帖。这类帖子被标成 `uncertain`，需要你去广场人工确认。
- **账号被限制或 Key 失效时自动暂停**并记录原因，`resume` 才会继续。
- 官方硬上限 **100 帖/天、400 次上传/天**；本工具默认自限 12 帖/天、最小间隔 45 分钟。

## 内容是怎么保证不胡说八道的

这是整个项目的核心，三层：

1. **事实契约**：每条素材的 `facts` 是唯一允许被引用的数字来源。模版用 `requires` 声明它需要哪些字段，缺了就**整条模版跳过**，不会渲染出空洞或占位符。
2. **事实台账**：渲染时每个被吐出的数字都记进 ledger。生成后把正文里所有数字和 `$币种` 反查台账，出现没有来源的数字即判定失败。
3. **AI 只做改写**：润色层拿到的是已经填好事实的文本，返回后必须通过同一套台账校验 + 标签增删检查 + 行数漂移检查 + 长度检查，**任何一条不过就退回模版原文**。所以模型不能创造数字。

另外：敏感词过滤、原文近似去重、**结构签名去重**（把 `$币种`/`#话题`/数字掩码后再比，专治"同一句话换个币"）、素材指纹去重（同一事件被多家报道只发一次）。

去重的比较对象是**已发布 / 已放行 / 状态未知**的帖子，不含仍在审核的草稿——否则草稿积压会互相挡死，任何重写都会被判重复。放行时会提示结构重复，发布前还有一道兜底（CLI 批量放行也绕不过），命中就退回草稿而不是发出去。

### 标点约定

`take.*`（观点类词库）**不带句号**，由模板负责标点，因为部分引用点在句中；`phrase.*`（独立成句的免责/风控话术）**自带句号**。违反这条会产生"榜首的持续性通常比涨幅本身更值得看你上车了还是在等？"这种黏句——`test/engine.test.ts` 里有静态检查守着，同时守着的还有词库重复键（JS 对象字面量后写静默覆盖前写，运行时看不出）。

## 选题逻辑

**广场决定写谁，行情数据决定写什么。**

- 读币安广场自己的公开 JSON 接口拿实时热门话题与热帖，聚合出「此刻广场在讨论哪些币」
- 对这批候选币拉币安合约行情（涨跌、量能倍数、资金费率、持仓变化、多空比）
- 合成热度分，要求**持续采样到成熟**才发（默认门槛 45 分、持续 40 分钟、至少 4 次采样），一个上涨周期只发一条（认领后 6 小时冷却）
- 单一信号不采信：只有一路指标显著时分数打折，避免把一根插针当趋势

这是"发专帖不抢第一波"的取舍：帖子会带上「这个状态已经持续约 2.5 小时」这类**只有持续采样才写得出来**的句子。

## 面板

概览 · **账号**（矩阵、启停、每号 Key/代理/人设/节奏） · 热度榜 · 素材库 · 发帖队列（含 K 线缩略图、通过/驳回/编辑） · 模版（权重与启停） · 设置（节奏与时段与风格与保留期） · 接入与 AI（广场 Key、AI 供应商、拉取模型、连通测试）

**发帖队列的「溯源」面板**是排障主入口，每条帖子可展开看到：

- 原始素材（类目/子类型、热度、来源、时间、全部引用字段）
- 命中的模版（id、风格、权重、**模版源码**可折叠查看）
- 生成过程：`seed`（可复现）、用到的词库键、随机池选中哪一项、走了哪个条件分支、AI 润色是"通过"还是"被拒+原因"
- **事实台账**：正文里每个数字对应哪个字段，一眼看出有没有凭空出现的数
- 两个动作：**同模版换一批**（换 seed 重采样词库与分支）、**用所选模版重写**（同素材换角度，强制该模版、不静默回退）

重写只改措辞，素材事实不变，结果同样要过事实台账校验。

## 已知边界

- 广场读接口是**未公开的内部接口**，随时可能改；每个采集器都是失败降级而非崩溃。
- 效果数据只能从榜单里"碰巧扫到"自己的帖子，扫不到就是没有，不会显示成 0。
- 爆仓监控需要常驻 WebSocket，尚未接入。
- 自动发布依赖你自己判断平台规则风险——工具能保证的是不刷量、不重复、不编数据，**保证不了不被平台限流**。
